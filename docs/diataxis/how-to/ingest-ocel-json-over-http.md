# Ingest OCEL JSON over HTTP (how-to)

Goal: POST OCEL 2.0 JSON into beam4pm's own network-facing ingest endpoint
and get typed admit/refuse responses — no bridge code, no client library.

The endpoint is `BeamPM.OcelIngest.Router` (`lib/beam4pm_ocel_ingest.ex`),
a Plug router GENERATED by ggen_igniter from the admitted
`bpmi:AdmittedIngestRoute` graph in `ontology.ttl`. Its contract, from the
`@moduledoc`:

- `POST /ocel/events` — decodes into the admitted `ocel_event` record type
- `POST /ocel/objects` — decodes into the admitted `ocel_object` record type
- anything else is a real `404` (`route_not_admitted`) — never a silent
  catch-all

## 1. Start the router

The router does not persist anything; it decodes and answers. Mount it in
your own `Plug.Router` stack or run it in a dev Bandit/Cowboy wrapper. For
a one-off check, call it in-process:

```elixir
# in `iex -S mix` (or a mix run -e block)
conn =
  Plug.Adapters.Test.Conn.conn(%Plug.Conn{}, :post, "/ocel/events", nil)
  |> then(&%{&1 | body_params: %{"events" => [event_json_map]}})
  |> BeamPM.OcelIngest.Router.call(BeamPM.OcelIngest.Router.init([]))
```

## 2. The payload shape

Event batches:

```json
{
  "events": [
    {
      "event_id": "evt-1",
      "event_type": "order.place",
      "event_time": "2026-10-01T00:00:00Z",
      "attributes": {"trace_id": "t1", "object_ids": ["order-1"]}
    }
  ]
}
```

Objects ride the `/ocel/objects` route with `object_id`/`object_type`
(`lib/beam4pm_ocel_ingest.ex`, `post("/ocel/objects")`).

## 3. The response contract

Per the `@moduledoc`: every path returns a typed JSON response, never a
crash:

- `200`/`201` — real admitted decode into a
  `%BeamPM.Types.OcelEvent{}`/`%BeamPM.Types.OcelObject{}`
- `422` — real validation refusal from the generated `new/1` constructor
- `404` — any route not in the admission graph

Malformed or unadmitted payloads are refusals, not exceptions: the
generated constructor's field-presence validation is exercised on every
payload.

## 4. Where the decoded events go

The router decodes and answers; it does not buffer. Feed the returned
structs to `BeamPM.Ingest.Bridge.ingest/1` (the bounded ETS buffer,
`scripts/ingest_telemetry.exs`) or store them in your own Ash/ETS state —
mirroring `BeamPM.Ocel.object_trace/2`'s contract that the caller owns
accumulation (see `lib/beam4pm_ocel.ex` `@moduledoc`).
