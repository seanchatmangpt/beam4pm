# beam4pm v26.8.29 — Cloud Marketplace Revenue Operations Charter

Status: `PARTIAL_ALIVE` — documentation bootstrap only; no runtime or marketplace listing evidence yet.

## Mission

`beam4pm` is the first ggen-only product proof: a BEAM-first process-mining and process-intelligence platform manufactured from admitted declarative knowledge. Human and LLM direct source-code commits are forbidden by default. `beam4pm_pro` is the commercial distribution and operating layer intended to turn living services into continuously inferred, locally governed process intelligence with zero mandatory application rewrites and an air-gapped operating mode.

The commercial working-backwards promise is:

> Buy from the customer's cloud marketplace, deploy into the customer's environment, and go from no process visibility to a continuously maintained process-intelligence system with minimal configuration, no required vendor SaaS dependency, and no mandatory telemetry export.

The product loop is:

`living services -> discovery -> telemetry -> service graph -> process inference -> process twin -> conformance -> optimization/planning -> admitted actuation -> receipt -> new observation`

## Non-negotiable manufacturing doctrine

1. `wasm4pm` is sunk cost and is not an architectural dependency, source tree, compatibility target, or implementation shortcut.
2. `beam4pm` starts from scratch.
3. Normal executable source authority belongs to ggen/manufacturing, not humans or LLMs.
4. Humans/LLMs may change admitted manufacturing inputs: ontology, schemas, specifications, templates, queries, generators, acceptance definitions, and other declarative knowledge surfaces.
5. Direct handwritten source is a break-glass exception only: explicit temporary privilege, one pure commit, exact-subject Chicago execution, receipt/replay evidence, and immediate privilege revocation.
6. Generated output is not an editing surface. A generated defect is repaired upstream and regenerated.
7. Modern Erlang/OTP and Gleam are first-class targets, with working `examples/` and `playground/` as release gates.
8. Elixir/Ash are first-class projections, not the mandatory interop path for Erlang or Gleam.
9. Rust4PM documentation/types may be used as external semantic evidence and reference input; source-code porting is not the reconstitution strategy.
10. Planner/model output never carries ambient execution authority. SELECT, CONSTRUCT, and DO remain separate; BRCE is the exclusive DO path.

## Product split

### beam4pm — open process substrate

Owns the canonical process/event model and generated BEAM-facing projections: Erlang, Gleam, Elixir, Ash, OCEL/XES, DFGs, Petri nets, alignments, conformance, discovery, formal model projections, codecs, APIs, examples, playground, tests, and process-inference primitives.

### beam4pm_pro — commercial process-intelligence product

Adds zero-config discovery, OpenTelemetry/Weaver integration, Kubernetes topology, eBPF/zero-code observation, continuous process inference, living process twins, anomaly/conformance analysis, WIP/throughput/bottleneck analysis, planning/optimization, enterprise governance, BRCE actuation, receipts/replay, fleet management, air-gap operations, supportability, and cloud marketplace packaging.

## Revenue thesis

`beam4pm_pro` is the commercial front door because it can sell an observable consequence before asking the customer to adopt the rest of the architecture:

`deploy -> observe -> infer -> quantify -> expand`

It monetizes systems the customer already owns, can initially operate with zero production DO authority, can prove ROI using process metrics, and can expand across both capability depth and estate coverage. The rest of the ecosystem becomes pull-through infrastructure: ggen as manufacturing moat, marketplace packs as accumulated executable knowledge, planning as future search, AutoFDE as diagnosis/repair, GymAct as falsification, and BRCE as governed actuation.

## TAI operating model applied

This package intentionally uses the operating discipline associated with Technology Applications Inc. (TAI): customer mission first, Total Quality Leadership, full lifecycle responsibility, configuration/document control, validation and verification, auditability, supportability, standards compliance, continuous improvement, and evidence of completed work rather than unsupported claims.

Applied to beam4pm, this means cloud marketplace publication is not the finish line. The finish line is a repeatable contract-to-renewal operating system with traceable entitlement, deployment, support, evidence, economics, quality, and mission outcomes.
