# How to Run GATE M2 Safely and Diagnose a Failure

GATE M2 proves that `ggen`'s output is a pure function of `(ontology.ttl, pack templates)`
with no dependency on prior disk state, by deleting every manufactured file and regenerating
it (`scripts/gate_m2_check.sh:2-12`). Because it deletes real files, run it only against a
scratch clone — never the live tree you're editing in.

## Prerequisites

- A separate scratch clone of this repo, with submodules initialized
  (`vendor/ggen-marketplace` is a submodule — CLAUDE.md build section).
- `ggen`, `rebar3`, `mix`, `erlc`/`erl` on `PATH` (the same tools `just verify` needs).

## Steps

### 1. Make a scratch clone — do not run this in your working tree

```sh
git clone --recurse-submodules /Users/sac/beam4pm /tmp/beam4pm-gate-m2-scratch
cd /tmp/beam4pm-gate-m2-scratch
```

The script deletes every file it finds under `SEARCH_DIRS=(src lib test gleam/src gleam/test
schema docs/reference)` (`scripts/gate_m2_check.sh:17`) that carries the `GENERATED by ggen`
marker in its first 3 lines. If regeneration fails partway (e.g. a `mix compile
--warnings-as-errors` failure inside `igniter_sync.sh`), `set -euo pipefail`
(`scripts/gate_m2_check.sh:13`) aborts the script and you're left with deleted-and-not-yet-
regenerated files. That's an acceptable state to hit in a scratch clone; it is not acceptable
in a tree with uncommitted work.

### 2. Run the gate

The script `cd`s to the repo root itself (`scripts/gate_m2_check.sh:14`), so run it from
anywhere inside the clone:

```sh
bash scripts/gate_m2_check.sh
```

### 3. Read what it's doing while it runs

In order, the script:

1. Locates all manufactured files by marker and sha256s them — the "before" set
   (`scripts/gate_m2_check.sh:48-53`).
2. Stashes `test/beam4pm_actuation_k8s_test.exs` and
   `test/beam4pm_process_governor_k8s_test.exs` to a `mktemp -d` dir
   (`scripts/gate_m2_check.sh:78-94`), restored via an `EXIT` trap. These two hand-authored
   tests reference manufactured modules at compile time and would otherwise fail with
   `UndefinedFunctionError` mid-regeneration-window.
3. Deletes exactly the found "before" files (never a whole directory,
   `scripts/gate_m2_check.sh:97`) and `ggen.lock`, then runs `ggen sync run`
   (`scripts/gate_m2_check.sh:98-99`).
4. Runs the second-engine and per-family sync scripts in a documented order
   (`scripts/gate_m2_check.sh:100-147`): `igniter_sync.sh`, `receipt_chain_sync.sh`
   (`:110-111`), then — after sourcing `scripts/env/rust4pm_reactor_env.sh` — `rf1_dfg_sync.sh`,
   `rf2_conformance_sync.sh`, `rf3_ocel_sync.sh` (`:118-121`), then `revenue_economics_sync.sh`,
   `revenue_metering_sync.sh`, `claude_workflow_reactor_sync.sh` (`:125-127`), then the
   `pro_*_sync.sh` family plus `pro_type_pages_sync.sh` (`:135-147`).
5. Restores the stashed test files explicitly (`:153`), re-locates manufactured files, and
   sha256s the "after" set (`:156-158`).
6. Compares before/after checksums (`:160-166`).

### 4. Read a PASS

```
GATE M2: PASS -- N manufactured files byte-identical across delete+regenerate
```

Exit code 0. `N` manufactured files were deleted and regenerated byte-identically.

### 5. Diagnose a FAIL

A checksum mismatch prints to stderr:

```
GATE M2: FAIL -- regenerated output differs from the deleted originals
```

followed by a unified-style diff of the sorted `sha256sum` listings
(`scripts/gate_m2_check.sh:161-163`), exit code 1. Diagnose by working from the diff:

- **A specific file's hash changed but the file still exists** — non-determinism in `ggen`
  itself, or an edit to `ontology.ttl` or the vendored pack's templates
  (`vendor/ggen-marketplace/packs/beam4pm-process-model-pack`) that only partially propagated.
  Re-run `just sync` (`rm -f ggen.lock; ggen sync run --dry-run; ggen sync run`, Justfile:12-15)
  by hand in the scratch clone and inspect `git diff` on the affected file.
- **A file present in "before" is missing from "after"** — one of the ordered sync scripts at
  step 4 above didn't run, or ran but didn't produce that file. Check which
  `scripts/<name>_sync.sh` owns that module family (CLAUDE.md's "Other generated modules"
  list) and run it standalone in the scratch clone to see its own error output.
- **The script aborts before printing PASS or FAIL at all** — one of the `bash
  scripts/*_sync.sh` invocations exited nonzero and `set -euo pipefail`
  (`scripts/gate_m2_check.sh:13`) killed the whole run. The `EXIT` trap still restores the two
  stashed k8s test files even in this case, so re-running the script from the same scratch
  clone is safe; the actual error will be higher up in the same terminal output, inside the
  failing sync script's own stderr.

### 6. Clean up

```sh
cd /
rm -rf /tmp/beam4pm-gate-m2-scratch
```

Never point this script at the repo you're actively editing — it exists to prove
determinism on a clone, not to regenerate your working tree. If you actually want to
regenerate manufactured files in your working tree, use `just sync` or one of the specific
`scripts/<name>_sync.sh` scripts instead.
