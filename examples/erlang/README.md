# OCEL Log Demo (Erlang)

## What this is

`ocel_log_demo.erl` is a real, runnable `escript` that exercises
`beam4pm_types`, the ggen-manufactured Erlang module generated from the
admitted `bpm:RecordType` RDF/SHACL graph. It is not a stub or a
hand-simulated version of the constructor's behavior: it calls the real
`beam4pm_types:new_ocel_event/1` for each of three sample events, pattern-
matches on the real `{ok, Event}` / `{error, Reason}` return shape defined
in the generated source, and halts with a non-zero exit code and a printed
error the moment any construction fails.

The generated module lives at:

```
/Users/sac/beam4pm/generated/erlang/src/beam4pm_types.erl
```

generated from the ggen template at:

```
/Users/sac/beam4pm/vendor/ggen-marketplace/packs/beam4pm-process-model-pack/templates/beam4pm_types.erl.tmpl
```

(the same pack also exists at
`/Users/sac/ggen-marketplace/packs/beam4pm-process-model-pack/`). Its header
comment reads `GENERATED by ggen from the admitted bpm:RecordType graph. Do
not edit.` -- this demo treats it as exactly that: a real compiled
dependency, not source to copy from.

`beam4pm_types:new_ocel_event/1` has the spec:

```erlang
-spec new_ocel_event(map()) -> {ok, ocel_event()} | {error, {missing_field, atom()}}.
```

It checks `event_id`, `event_type`, then `event_time` (in that order) and
returns `{error, {missing_field, FirstMissingKey}}` on the first one absent
from the input map; `attributes` is optional. This demo's `main/1` matches
`{ok, _Event}` for the happy path and `{error, Reason}` for the failure
path, printing `Reason` to stderr and calling `halt(1)` on failure -- it
never silently swallows a constructor error.

## Why the printed summary reads from the source map, not the record

`beam4pm_types.erl` defines `#ocel_event{}` internally and does **not**
ship a `.hrl` header or export any field-accessor functions (confirmed by
reading the generated source and its own EUnit test file,
`generated/erlang/test/beam4pm_types_tests.erl`, which likewise only ever
asserts `{ok, _}` and never destructures the record). That means an
external module genuinely has no supported way to read `event_id` /
`event_type` back out of the returned `#ocel_event{}` without redeclaring
the record definition itself -- which would silently drift the moment the
generator reorders or renames a field.

Given that real constraint, this demo prints `event_id` / `event_type` from
the same source map it already built to call the constructor, rather than
reaching into `beam4pm_types`'s private record layout. The constructor call
and its `{ok, _} | {error, _}` match are still real and still gate the
non-zero-exit behavior -- only the two printed fields are read from data the
caller already had on hand.

## How to run it (verified against Erlang/OTP 28.3.1)

Compile the generated module to a scratch `ebin` directory, then run the
escript, passing that `ebin` directory as the script's own first argument
so `main/1` can add it to the code path with `code:add_patha/1`:

```sh
mkdir -p /tmp/beam4pm_ebin
erlc -o /tmp/beam4pm_ebin /Users/sac/beam4pm/generated/erlang/src/beam4pm_types.erl
escript examples/erlang/ocel_log_demo.erl /tmp/beam4pm_ebin
```

Expected output:

```
ocel_event id=e-001 type=order_placed
ocel_event id=e-002 type=payment_received
ocel_event id=e-003 type=order_shipped
```

### On the task's originally suggested invocation

The form `escript -pa /tmp/beam4pm_ebin examples/erlang/ocel_log_demo.erl`
does **not** work against this environment's `escript` (OTP 28.3.1): it was
tried and fails with `escript: illegal operation on a directory:
'/tmp/beam4pm_ebin'` -- `escript`'s own argument parser does not consume
`-pa <dir>` as a flag+value pair the way `erl` does, so the directory ends
up misparsed as the script filename. Two invocations were tried and
confirmed working instead, in order of preference:

1. **Pass the `ebin` directory as the script's own first argument** (shown
   above). `main/1` calls `code:add_patha/1` on it directly. This is
   self-contained and does not depend on shell/OS environment state.
2. **Set `ERL_FLAGS`**, which `erl` (and therefore the runtime `escript`
   launches) reads on startup:

   ```sh
   ERL_FLAGS="-pa /tmp/beam4pm_ebin" escript examples/erlang/ocel_log_demo.erl
   ```

If `beam4pm_types` is not reachable by either method, the script fails
loudly with `beam4pm_types:new_ocel_event/1` undefined (a real
`undefined function` exception from the Erlang runtime, exit code 127) --
this was also verified directly rather than assumed.
