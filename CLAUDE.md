# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## What this repo is

beam4pm is a BEAM-first process-mining substrate whose application source is
manufactured entirely by [ggen](https://github.com/seanchatmangpt/ggen) from
`ontology.ttl` (this repo's own RDF instance data) plus a vendored
ggen-marketplace pack at `vendor/ggen-marketplace/packs/beam4pm-process-model-pack`
(the `bpm:` vocabulary — `bpm:RecordType`, `bpm:Field` — and the code templates).
There is no `generated/` directory: manufactured code lives in the same `src/`,
`lib/`, `test/`, `gleam/`, `schema/`, and `docs/reference/` directories
hand-authored code would use. Provenance is per-file, signalled by a
`GENERATED by ggen ... Do not edit.` header as the first non-shebang line —
never by directory placement.

## Source-authority doctrine (read before editing anything)

Direct edits to application source are refused by default, for humans and LLMs
alike. Check the first line of any file before editing it:

- **`GENERATED by ggen ... Do not edit.`** — this is ggen output. Never hand-edit
  it, regardless of directory. If it's wrong, fix `ontology.ttl` or the pack's
  templates in `vendor/ggen-marketplace/packs/beam4pm-process-model-pack`, then
  regenerate (`rm ggen.lock && ggen sync run`).
- Everything else is a legitimate manufacturing input and may be hand-edited:
  `ontology.ttl`, `ggen.toml`, `rebar.config`, `mix.exs`, `src/beam4pm.app.src`,
  the vendored pack's templates, docs, and the shell/Elixir sync scripts under
  `scripts/`.

Full doctrine, including the narrow receipted privileged-exception path for
direct intervention on generated files:
`docs/jira/v26.8.29/03-architecture-and-ggen-manufacturing.md`.

## Build, sync, and test

```sh
git clone --recurse-submodules <this-repo-url>   # vendor/ggen-marketplace is a submodule
just verify        # submodules -> sync -> authorship -> engine_dispatch -> lint_truth -> test
just sync           # rm ggen.lock; ggen sync run --dry-run; ggen sync run
just test           # rebar3 eunit && mix test
```

`make verify` is a lighter, legacy alias (`submodules -> sync -> test` only) that
predates the authorship/engine_dispatch/lint_truth gates below — it is not
equivalent to `just verify`; prefer `just verify` (or the raw commands) when you
need the full chain.

Equivalent raw commands:

```sh
git submodule update --init --recursive
rm -f ggen.lock && ggen sync run --dry-run && ggen sync run
rebar3 eunit        # Erlang test suite over generated src/*.erl
mix test             # Elixir test suite over generated lib/*.ex
```

- `rebar3 eunit` and `mix test` are the two real test entry points (no single
  jest/pytest-style "run one test" flag beyond each tool's own filters — use
  `rebar3 eunit --module=<mod>` / `mix test <path>:<line>`).
- `bash scripts/roundtrip_check.sh` — GATE M5: proves wire-format identity
  across all three BEAM-side projections by round-tripping every admitted
  `bpm:RecordType` record (full + minimal variants) through the generated JSON
  codecs in three directions — `elixir-verifies-erlang`, `erlang-verifies-elixir`,
  and `ash-verifies-wire` (580 pass per direction: 290 record types x
  full/minimal). The Ash leg's identity relation is `DateTime.compare == :eq`
  for datetime fields, not byte identity, and Ash's own `:id` primary key is
  disclosed as Ash-only (not part of the wire contract). Gleam has no wire
  codec projection yet, so it isn't part of this proof.
- `bash scripts/gate_m2_check.sh` — the authoritative determinism gate: finds
  every file carrying the `GENERATED by ggen` marker under
  `src, lib, test, gleam/src, gleam/test, schema, docs/reference,
  infra/gcp/cloudrun, infra/gcp/packer, .github/workflows` (recursive —
  a `-maxdepth 1` miss on `gleam/src/beam4pm/*.gleam` was a real prior bug;
  the 3 github-actions-pack workflows were invisible to it until the pack
  emitted the marker in 0.2.4), deletes exactly those files, regenerates, and
  diffs — proving ggen is a pure
  function of `(ontology.ttl, pack templates)` with no dependency on prior
  disk state. Never sweeps `gleam/build/` (compiled artifacts, not manufactured
  source). Destructive by design (backed by an EXIT-trap backup/restore — a
  SIGKILL mid-run skips the trap); not part of `just verify`, but is a
  standalone step in CI (`.github/workflows/beam4pm-ci.yml`).
- `bash scripts/gate_authorship_check.sh` — GATE AUTHORSHIP: every file under a
  manufactured root that carries no `GENERATED` marker must be one admitted
  `bpm:HandAuthoredSource` individual in `ontology.ttl` (path, closed kind,
  principal, reason, acceptance command, sha256, expiry, sunset plan), rendered
  by ggen into `schema/beam4pm_hand_authored_source.tsv` (what the gate reads)
  and the counted ledger `docs/reference/beam4pm_hand_authored_source.md`.
  Refuses `REFUSED_UNADMITTED` / `_STALE_ADMISSION` / `_CONTRADICTION` /
  `_SHA_DRIFT` / `_EXPIRED`; `--exercise` also runs every acceptance command.
  Runs in `just verify`, CI, and the manufactured
  `test/beam4pm_authorship_gate_test.exs`. Adding or editing a hand-authored
  file under `src/ lib/ test/ gleam/src gleam/test schema/ docs/reference
  infra/gcp/{cloudrun,packer}` therefore means editing `ontology.ttl` (new or
  re-digested individual) and regenerating in the same commit.
- `bash scripts/gate_engine_dispatch_check.sh` — GATE ENGINE DISPATCH: every
  manufactured native-engine facade op (rendered from the `bpm:Engine` /
  `bpm:EngineOp` / `bpm:EngineArg` facts in `ontology.ttl` into
  `schema/beam4pm_engine_ops.tsv`) must be an op its crate's dispatch match
  actually handles — a fact naming an op the crate doesn't dispatch would
  otherwise render a compiling facade whose call always returns "unknown op".
  Refuses `REFUSED_MANIFEST_*` and `REFUSED_OP_NOT_DISPATCHED` /
  `REFUSED_ENGINE_NOT_DISPATCHED`. Runs in `just verify` and CI.
- `bash scripts/gate_lint_truth.sh` — GATE LINT-TRUTH: a static scanner (ported
  from ex4pm's `mix ex4pm.lint.truth`) over `docs`, `README.md`, `CLAUDE.md`,
  and `CONTRIBUTING.md` for the banned overclaiming phrases enumerated at the
  top of the script itself (an unscoped claim of production readiness is one
  of them). Runs in `just verify` and CI — the same discipline this file's
  own authors have to satisfy when editing this file.
- `bash scripts/igniter_sync.sh` — the second, Elixir-native manufacturing
  engine (`ggen_igniter` hex package) that produces the Ash projection under
  `lib/beam4pm_ash/` (one `Ash.Resource` module per admitted record type) plus
  `lib/beam4pm_ash_domain.ex` and `lib/beam4pm_ash_roundtrip.ex`; its manifest
  probe must render byte-identical to the Rust ggen output.
- `bash playground/playground.sh` — full fresh-clone workflow: manufacture, all
  three test suites, real discovery demos per language, roundtrip proof.
- Other `scripts/*_sync.sh` (`rf1_dfg_sync.sh`, `rf2_conformance_sync.sh`,
  `rf3_ocel_sync.sh`, `receipt_chain_sync.sh`, `process_governor_sync.sh`,
  `actuation_sync.sh`) each regenerate one specific manufactured module family
  named by the script — use the matching script rather than a blanket
  `ggen sync run` when iterating on one ontology slice.

## Architecture

**Manufacturing pipeline:** `ontology.ttl` (this repo's `bpm:RecordType` /
`bpm:Field` individuals) + the vendored pack's templates → `ggen sync run` →
per-language projections written into `src/` (Erlang), `lib/` (Elixir),
`gleam/src/` (Gleam), `schema/*.schema.json` (wire-format JSON Schema), and
`docs/reference/` (generated reference docs). `ggen.lock` pins the last sync;
deleting it and re-running is how a clean-slate regeneration is forced.

**Four language projections of the same 290 record types**, each independently
generated from the same ontology:
- **Erlang** (`src/`) — `new_<type>/1` validating constructors returning
  `{ok, Record}` / `{error, {missing_field, Field}}`; `beam4pm_types_manifest`
  reflects every admitted type and its fields.
- **Elixir** (`lib/`) — same shape, plus `BeamPM.Types.Manifest`.
- **Gleam** (`gleam/src/beam4pm/`) — note: `discovery.gleam` and `types.gleam`
  live nested one level under `gleam/src/beam4pm/` (Gleam's own package-name
  convention), not directly under `gleam/src/`. Two disclosed type divergences
  from the Erlang/Elixir projections are noted in its generated comments. No
  wire codec leg yet — the GATE M5 roundtrip proof covers Erlang, Elixir, and
  Ash only (see `roundtrip_check.sh` above).
- **Ash** (`lib/beam4pm_ash/resources/*.ex`) — 290 `Ash.Resource` modules (one
  per admitted record type, e.g. `BeamPM.Ash.Resources.EventType`), plus
  `lib/beam4pm_ash_domain.ex` (`BeamPM.Ash.Domain`) and
  `lib/beam4pm_ash_roundtrip.ex` (the GATE M5 third-direction fixture runner).
  All manufactured by the separate `ggen_igniter` engine
  (`scripts/igniter_sync.sh`), not the primary Rust ggen pipeline.

**Record domains** (see `docs/reference/beam4pm_types_reference.md`, itself
ggen-generated, for the field-level reference): event/log identity
(`ocel_event`, `ocel_object`, `event_log`, `event_type`, `object_type`, …),
process models (`dfg_edge`, `petri_place`, `petri_transition`, `path_schema`,
`heuristic_arc`, …), conformance/alignment (`alignment_move`,
`conformance_result`, `oc_declare_constraint`, `process_variant`,
`case_stats`, …), and adjacent runtime/planning/policy/tracing/security types
(`resource_allocation`, `k8s_object_ref`, `planning_action`,
`policy_decision`, `service_span`, `span_edge`, …).

**Process-mining behavior** (generated, not hand-written): codecs
(`beam4pm_codec` / `BeamPM.Codec`, map↔JSON both directions) and discovery/
conformance (`beam4pm_discovery` / `BeamPM.Discovery` /
Gleam `beam4pm/discovery` — `traces_from_events/2`, `dfg_from_traces/1`,
`conformance/2`). No alignment search, no Petri-net replay.
`conformance_result.precision` IS computed in all three projections — real
ETC (escaping-edges) precision via `beam4pm_precision:etc_precision/2,3`
(Erlang/Elixir) and `beam4pm/precision.etc_precision` (Gleam,
`gleam/src/beam4pm/precision.gleam`).

Discovery also has a second, causal reading over OpenTelemetry-style tracing
spans (`service_span.parent_span_id`/`span_id`), in all three projections:
`traces_from_spans/1` (one trace per `trace_id`, temporal-adjacency ordering)
and `causal_dfg_from_spans/1`, which classifies each directly-follows edge as
`observed` (a real parent/child span link), `adjacent` (time-adjacent only,
no causal link), `inferred_only`, `observed_not_adjacent`, or an orphan —
distinct from, and not a replacement for, the pre-existing temporal-adjacency
discovery over `ocel_event`/`log_trace`.

**Native engine facades**: four native engines are hosted inside BEAM via
`wasmex` (thin Erlang/Elixir/Gleam facade triples, one per engine) — all four
(`petgraph`, `tract`, `rust4pm`, `ferroplan`) are now manufactured from
`bpm:Engine`/`bpm:EngineOp`/`bpm:EngineArg` facts in `ontology.ttl` via one
igniter template family; `scripts/gate_engine_dispatch_check.sh` holds each
facade's op set to exactly what its crate's own dispatch match actually
handles (73 wire ops across the four engines, 0 unexposed). The
`native_engine_facade` `bpm:HandAuthoredSource` kind's debt ceiling stays at 6
in the ontology as a deliberate historical marker, but the real admitted
count for that kind is now 0 — see `docs/reference/beam4pm_hand_authored_source.md`
for the current ledger (14 debt items remain, none of them engine facades).

**Formal projection**: admitted `bpmg:ProcessContract` graphs also project
into PDDL (`schema/pddl/<contract_id>.{domain,problem}.pddl`, GENERATED),
solved by the real `ferroplan` planner via `BeamPM.Ferroplan.plan_production/4`
— one real executed leg of the `canonical graph -> formal projection ->
analysis/planning/verifier result` loop described in `VISION-2030.md`
(sections 10-11); POWL/Petri/PPDDL/HDDL projections don't exist yet.

**Other generated modules** worth knowing by name when tracing a bug:
`beam4pm_ai_contracts(_codec)`, `beam4pm_billing`, `beam4pm_entitlement`,
`beam4pm_precision`, `beam4pm_process_governor`, `beam4pm_receipt_chain`,
`beam4pm_rf1_dfg`, `beam4pm_rf2_conformance`, `beam4pm_rf3_ocel`,
`beam4pm_roundtrip`, `beam4pm_actuation` — each has a matching
`scripts/<name>_sync.sh` that regenerates just that family.

**`beam4pm_pro`** is a planned future commercial layer on top of this
substrate; `beam4pm_billing` (`src/beam4pm_billing.erl`, MP6 reconciliation)
and `beam4pm_entitlement` (`src/beam4pm_entitlement.erl`, MP3 reconciliation)
already exist as real code with matching eunit+ExUnit tests — the remaining
gap is marketplace/pricing/RevOps tooling, not these core reconciliation
modules.
